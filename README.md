# 胶片试映排期台

在胶片分镜条核对台基础上扩出的纯前端本地试映排期应用：整理片段、维护修复状态与时长、批量排片、排期表/统计/提醒同步，刷新后数据保留。无第三方依赖、无后端服务，直接打开 `index.html` 即可使用（或在本目录起静态服务）。

## 预置数据

- 三名放映员、两个影厅（一号厅容量 4:00、二号厅容量 6:00）
- 六个片段：完好可排、已修复可排、破损未修复禁排各有代表

## 排片规则

一次可填多排片行（选片段、影厅、放映员与连续时段的开场时间，结束时间按时长自动推算）。点「整批保存排期」时整批校验：

1. 每行片段/影厅/放映员/时间齐全；
2. 片段必须完好或已标记修复，未修复禁排；
3. 同一放映员在本批内或与原排期的时段不得重叠，同一影厅同理（首尾相接不算冲突）；
4. 影厅待映总时长（本批新增 + 原有待映）不得超过厅容量，已完成场次不占未来容量。

任一行不满足，**整批不保存，原排期一条不动**，问题逐条列出。

## 退档规则

片段修复状态或时长发生变化后，使用该片段的全部**待映场次自动退回待排**（从排期表撤下，可重新排）；**已完成场次一律保留**，沿用完成时记录的时长。片段若仍有任意场次关联则不能删除。

## 统计与提醒

排期表、顶栏统计（待映场次/待排片段/已完成/待映总时长）、厅容量进度条与提醒均由同一份排期数据实时推导，任意改动后同步刷新；每分钟自动刷新开场/超时提醒。提醒包含：未修复禁排片段、可排但未排的待排片段、厅容量预警/超限、30 分钟内开场、正在放映、已过结束时间待补记完成。

## 存档

全部数据存于浏览器 `localStorage`（键 `zfl17-screening-desk-v1`），刷新保留；坏档会按字段归一化容错恢复。工具栏支持：

- 导出排期单（TXT）
- 存档导出 / 导入（JSON）

## 文件划分

- `rules.js` —— 业务规则：预置数据、批量校验与原子提交、退档、统计与提醒、时间格式化
- `archive.js` —— 存档：localStorage 读写与归一化、TXT/JSON 导入导出
- `page.js` —— 页面：DOM 渲染、表单与交互，只调用前两个文件暴露的接口
- `index.html` / `styles.css` —— 结构与样式
